# CRM — отдельное направление

CRM для сделок по импорту авто. Живёт внутри этого проекта, но не пересекается
ни с сайтом, ни с ботом: свой маршрут, свой вход, своя база.

## Что где лежит

| Слой | Где | Что делает |
|---|---|---|
| Интерфейс | `src/crm/` | React-приложение на маршруте `/crm/*`, отдельный чанк |
| API | `public/crm-api/` | PHP 8, единая точка входа `index.php` |
| Данные | `/www/private-crm/` на хостинге | SQLite, ключ сессий, необязательный `config.php` |
| Маршрутизация | `public/.htaccess` | `/crm/api/...` → `crm-api/index.php` |

Папка API называется `crm-api`, а не `crm/api`, намеренно. Если бы на диске
существовал каталог `crm/`, Apache считал бы `/crm` каталогом и отдавал 403
вместо приложения, а перезапись внутрь того же каталога зациклилась бы: после
внутренней перезаписи набор правил выполняется заново, и `[L]` это не
останавливает.

## Почему так, а не Next.js на Vercel

Исходная версия CRM была написана на Next.js с PostgreSQL. Перенести её в этот
проект как есть нельзя: сайт стоит на общем хостинге reg.ru, где нет Node.
Вариант с Vercel означал бы отдельный сервис, отдельный домен, токены от
владельца — и хранение персональных данных клиентов за рубежом. Последнее
прямо противоречит 152-ФЗ (ст. 18 ч. 5): CRM хранит ФИО, телефоны и VIN.
Заявки с сайта по той же причине уже принимает `public/api/lead.php` на
российском хостинге.

Бизнес-логика из прежней версии перенесена почти дословно — она не была
завязана на фреймворк: расчёт таможни, суммы сделки, этапы, сумма прописью,
состав публичных данных.

## Изоляция от сайта и бота

- **Код.** `/crm` грузится отдельным чанком. CRM не подключает каркас сайта,
  каталог, состояние витрины; сайт не подключает код CRM.
- **Доступы.** Своя таблица `crm_users`, свои пароли, своя кука `crm_session`
  с путём `/crm` — на страницы сайта она не отправляется вовсе. Ни админка
  сайта (`/admin`), ни список админов бота к CRM отношения не имеют.
- **Данные.** Своя база. Каталог бота лежит в Cloudflare KV и сюда не попадает.
- **Аналитика.** Переходы внутри `/crm` не отправляются в Метрику: внутренний
  раздел не должен портить отчёты по рекламе.
- **Поиск.** `robots.txt` закрывает `/crm`, страницы дополнительно ставят
  `noindex`.

## Первый запуск

1. Выложить сайт (обычный пуш — GitHub Actions выкатывает по FTP).
2. Открыть `https://автоимпорт-69.рф/crm` — пока в базе нет ни одного
   сотрудника, форма работает как создание владельца.
3. Создать владельца. После этого метод настройки отключается навсегда.
4. Завести менеджеров в разделе «Сотрудники», заполнить «Реквизиты».

База, каталог данных и ключ сессий создаются сами при первом обращении —
от владельца не требуется ни создавать БД, ни прописывать переменные.

> **Важно.** Пока владелец не создан, экран настройки открыт любому, кто знает
> адрес. Окно короткое и адрес нигде не публикуется, но пройти шаг 3 нужно
> сразу после выкладки, а не «когда-нибудь».

## Если на хостинге не окажется SQLite

API сам скажет об этом текстом ошибки. Тогда нужно создать базу MySQL в панели
хостинга и положить `/www/private-crm/config.php`:

```php
<?php
return [
    'driver' => 'mysql',
    'host'   => 'localhost',
    'name'   => 'u000000_crm',
    'user'   => 'u000000_crm',
    'pass'   => '...',
];
```

Схема применится сама при первом запросе. Правок кода не требуется.

## Что умеет

- **Темы.** Светлая и тёмная плюс «как в системе», переключатель в шапке.
  Выбор хранится в браузере сотрудника: тема — свойство устройства, а не
  учётной записи. Страница клиента и печатные формы всегда светлые.
- **Сделки.** Канбан из семи рабочих этапов плюс «завершена» и «отказ».
  На широком экране все этапы видны сразу, без горизонтальной прокрутки.
  Перетаскивание мышью и выпадающий список для телефона. Поиск по клиенту,
  телефону, VIN, марке и номеру; фильтр по менеджеру.
- **Реквизиты клиента.** ФИО полностью, дата рождения, паспорт, кем выдан,
  адрес регистрации, почта — подставляются в договор. Перед печатью видно,
  чего не хватает.
- **Деньги.** Цена в валюте закупки, курс (кнопка «ЦБ» тянет курс с
  cbr-xml-daily.ru через сервер), доставка, пошлина, утильсбор, брокер,
  прочее, комиссия, оплачено. Итог и остаток считаются на лету.
- **Калькулятор таможни.** Пошлина, утильсбор и сбор за оформление с показом
  формулы. Суммы переносятся в сделку одной кнопкой.
- **Задачи.** С исполнителем и сроком, быстрые кнопки «сегодня / завтра /
  через неделю», правка после создания, метка горящих на карточке доски,
  отдельная страница «мои / все».
- **Файлы.** Сетка превью, просмотр внутри интерфейса с перелистыванием
  стрелками, перетаскивание пачкой. До 8 МБ, до 60 на сделку, тип
  определяется по содержимому. Миниатюры делает сервер и кэширует рядом
  с базой: без них страница с тремя десятками фото тянула бы сотню мегабайт.
- **История.** Этапы, комментарии, правки сделки, задачи (поставлена,
  изменена, выполнена, возвращена, удалена) и файлы (загружен, удалён) —
  одной лентой.
- **Документы.** Счёт и договор — печать и сохранение в PDF браузером.
  Срок поставки и доля предоплаты берутся из сделки: по каждой машине
  договариваются отдельно.
- **Аналитика.** Выручка, прибыль, ожидаемые доплаты, средний чек, конверсия,
  средний срок, разрез по этапам и менеджерам.
- **Перезвон.** Дата и время обещанного звонка в сделке. На доске меткой,
  просроченный подсвечивается. Хранится без часового пояса — как назначил
  менеджер: перевод туда-обратно однажды приводит к звонку на три часа позже.
- **Уведомления.** Два канала. Telegram — свой бот CRM, отдельный от бота
  сайта; сотрудник привязывается одноразовым кодом из профиля. Браузерные
  push — дополнительно, включаются на каждом устройстве отдельно. Приходят
  о новой сделке, смене этапа чужой сделки, назначенной задаче и комментарии.
  Сбой отправки пишется в журнал и никогда не ломает работу: сделка важнее
  уведомления о ней.
- **Ссылка для клиента.** `/crm/track/<токен>` — этап, срок, фото и суммы.
  Наружу не уходят: закупочная цена, курс, расходы, комиссия, источник,
  ссылка на лот, заметки, ответственный. VIN маскируется, из файлов отдаются
  только помеченные как «Фото авто». Токен отзывается одной кнопкой.

## Чего пока нет

- **Журнал платежей.** `paid_amount` — одна цифра, а в жизни это предоплата,
  доплата после покупки и остаток при выдаче. Нужна отдельная таблица платежей.
- **Напоминания по расписанию.** Уведомления приходят на события. Чтобы
  утром приходил список просроченных задач и перезвонов, нужен планировщик
  в панели хостинга — отдельный шаг.
- **Заявки с сайта прямо в CRM.** Форма создаёт сделку в статусе «Новая заявка».

## Уведомления: как подключить

1. Владелец заводит бота у [@BotFather](https://t.me/BotFather) командой
   `/newbot` и вставляет токен в профиле, раздел «Бот уведомлений».
2. Нажимает «Проверить связь» — сервер спрашивает у Telegram, кто он такой,
   и подключает приём сообщений. Здесь же видно, если хостинг не выпускает
   запросы к `api.telegram.org`.
3. Каждый сотрудник открывает профиль, копирует код из шести символов и
   отправляет его боту. Код одноразовый.
4. Кнопка «Проверить» шлёт тестовое уведомление во все подключённые каналы.

Токен наружу не отдаётся никогда — ни в ответе API, ни на экране: показать
его один раз значит однажды показать на скриншоте. Интерфейс знает только,
настроен канал или нет.

**Про push на iPhone.** Safari умеет их с iOS 16.4, но только у сайта,
добавленного на домашний экран, и молча перестаёт присылать, если иконку
удалить. Поэтому основной канал — Telegram, а push — дополнение.

## Оговорки, которые важно помнить

- **Ставки таможни** в `src/crm/lib/customs-rates.ts` собраны на январь 2025 и
  с тех пор могли измениться. Калькулятор показывает это предупреждением.
  Это оценка для разговора с клиентом, а не расчёт для декларации.
- **Отправка в Telegram не проверена вживую с боевого сервера.** Код
  отправки прямолинеен, но выпускает ли хостинг запросы к `api.telegram.org`
  — вопрос к хостингу. Именно поэтому в интерфейсе есть кнопка «Проверить
  связь»: она отвечает на него за одно нажатие.
- **Шифрование push проверено встречной расшифровкой**, а не «должно
  работать»: PHP шифрует, Node тем же ключом читает; подпись VAPID проверена
  как ES256. Собственную криптографию нельзя считать рабочей, пока встречная
  сторона не прочла сообщение.
- **Шаблон договора** — рабочая заготовка. Ответственность сторон, возврат
  предоплаты и условия при задержке зависят от того, как вы договариваетесь
  на практике; шаблон стоит показать юристу до первого подписания.

## Тесты

```bash
npm test
```

41 тест на расчёты, где ошибка стоит денег: таможня, суммы сделки, сумма
прописью, маска телефона. Серверная формула сумм (`public/crm-api/lib/model.php`) намеренно
дублирует клиентскую (`src/crm/lib/money.ts`) — расчёт нужен и во время ввода,
и при сохранении. Совпадение проверено вживую на одних и тех же числах.
