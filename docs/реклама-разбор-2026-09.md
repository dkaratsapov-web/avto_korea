## 5. Замер сломан в трёх местах

Это важнее любого вердикта по кампаниям: часть выводов выше сделана вслепую.

**Заявки с главной не считаются ни одной целью.** Квиз на главной после
успешной отправки показывает «готово» прямо на месте и не уходит на `/thanks`,
а цель «Заявка с сайта» в Метрике — типа «переход по адресу» и ждёт именно
`/thanks`. JS-цели `lead_submit`, которую сайт отправляет в обоих сценариях, в
счётчике не заведено. Итог: заявка с квиза не попадает никуда.

При этом автоцель «отправка формы» за период сработала 96 раз: 37 — вход в
CRM, 33 — на главной, остальное по мелочи. Сколько из этих 33 доехало до
менеджера, по Метрике сказать нельзя — надо сверять с CRM.

**Старт бота не считается.** 77 кликов в бота, 0 стартов по цели tgtrack. Либо
связка со счётчиком не работает, либо никто из кликнувших бота не запускает —
и это два совершенно разных вывода с разными действиями.

**Второй домен не отдаёт события** (см. раздел 3) — 442 визита вслепую.

### Чтобы считать деньги

Расходы по кампаниям не выгружаются по двум независимым причинам:

- **API Директа** отвечает «Незавершённая регистрация»: приложению нужна
  заявка на доступ к API. Кабинет Директа → Настройки → «Доступ к API» →
  подать заявку для нашего приложения и дождаться подтверждения.
- **Расходы из Метрики** отвечают `403 direct_client_logins`: нужен логин
  рекламодателя. Переменную `DIRECT_LOGIN` в репозиторий добавили, но до
  сборщика она не дошла — `env-check.json` показывает «нет». Теперь сборщик
  читает её и из Variables, и из Secrets; добавить надо в
  GitHub → Settings → Secrets and variables → **Actions** → вкладка
  **Variables** → New repository variable, имя ровно `DIRECT_LOGIN`, значение —
  логин Яндекса, которому принадлежит кабинет Директа.

Без расходов нельзя посчитать цену перехода в канал и цену заявки. Всё, что
выше, — про качество трафика; сколько он стоит, покажет следующая выгрузка.
