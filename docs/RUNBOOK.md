# Как что делать — ДиАвто69

Пошаговые инструкции для типовых задач и поломок. Устройство системы — `docs/PROJECT.md`.

## Выложить правку
1. Проверки: `npm test`, `npx tsc --noEmit -p tsconfig.json`, `npm run build`, `php -l <файл>` для PHP.
2. Коммит, затем пуш в обе ветки:
   `git push -u origin claude/telegram-promotion-page-9llr6e` и `git push origin HEAD:claude/beautiful-goodall-irzq2f`.
3. Push в основную ветку запускает «Deploy site to reg.ru» (1–2 мин) и, если менялся `worker/`, «Deploy Telegram bot» (~1 мин). «Deploy site to Yandex» падает всегда — не обращать внимания.
4. Проверить живой сайт — «Site shots» (ниже).

## Посмотреть живой сайт
Из облачной сессии сайт напрямую не открывается (сеть сессии). Браузер работает на GitHub:
1. Запуск: Actions → «Site shots» → Run workflow (поле pages — страницы через запятую, click — CSS-селектор), или правка `site-shots.txt`, или из Claude через `actions_run_trigger`.
2. Через ~3 минуты: `git fetch origin site-shots && git show origin/site-shots:README.md`, картинки — `git archive origin/site-shots | tar -x -C <папка>`.
3. В отчёте: ответ и время по каждой странице (компьютер и iPhone 13), ошибки консоли, упавшие запросы, сдвиг вбок, чужие скрипты с началом кода, кто вызвал каждый внешний запрос.

Локально против своей сборки: `npx vite preview --port 4334` и `node scripts/site-shot.mjs --base http://localhost:4334 --pages /,/catalog --out <папка>`.

## SSL-сертификат
- Выпуск и продление — в панели хостинга reg.ru: ISPmanager → SSL-сертификаты → Добавить сертификат → Let's Encrypt. Домен автоимпорт-69.рф, в «Доменное имя» — и www.автоимпорт-69.рф, почта — обычная латиницей (кириллический адрес Let's Encrypt может не принять). Сертификат, выпущенный в панели, продлевается сам.
- Текущий: до 13.02.2027 (выпущен 15.11.2026, с www).
- «Site check» каждый день проверяет срок и падает, если осталось меньше 14 дней, — GitHub присылает письмо владельцу репозитория.
- Если браузер пишет «Не защищено», а проверка снаружи «ok» — у человека в браузере запомнилась старая ошибка: закрыть все окна и открыть заново или проверить в инкогнито.

## Бот: вебхук
- Вебхуки /tg и /max принимают только запросы с секретом. Секрет выводится из токена бота, хранить его отдельно не нужно.
- Если запрос пришёл без секрета (старая привязка или подделка), воркер отвечает 401 и сам перепривязывает вебхук с секретом, не чаще раза в 10 минут.
- Перепривязать вручную: в админке бота — кнопка переподписки вебхука (`webhook.setup`); или /setup?key=<токен> — только из доверенного места, токен в адресной строке не светить.
- Сменили токен бота — секрет поменяется сам, после деплоя вебхук перепривяжется на первом апдейте.
- Состояние — «Site check», шаг «Вебхук бота»: `pending_update_count` должен быть около 0, `last_error_message` — пустым.

## Бот MAX
- Токен — секрет Cloudflare `MAX_BOT_TOKEN` (ставит владелец в панели Cloudflare → Workers → diauto-bot → Settings → Variables and Secrets).
- Привязка — команда `/max` в Telegram-боте от владельца (подписка вебхука с секретом и команды).
- Посты канала уходят в канал MAX в том же виде, что в Telegram, но без ссылок и ников Telegram: «Связаться» → личка менеджера в MAX, «Бот» → бот в MAX.

## Раздел CRM «Каталог и бот»
1. Владелец пишет боту `/crm_admin` — бот присылает полный ключ.
2. Владелец вставляет его в CRM → «Каталог и бот» (подключение — только владелец).
3. После этого раздел работает у всех сотрудников; вкладка «Админы» — только у владельца.

## Контент-план в CRM
- Источник стартового плана — `context/content-calendar.md`. После правки: `node scripts/content-plan-json.mjs`. Если план изменился по существу — поднять `version` в скрипте: CRM предложит «Загрузить новый план» (сама не заменит — там могут быть правки и статусы).
- Бриф: вопросы — `src/crm/data/content-brief.json`, затем `node scripts/content-brief-md.mjs` (обновит `context/content-brief.md`). Ответы хранятся в CRM.
- Правило недели: минимум 1 Reels на ЦА Тверь — CRM подсвечивает неделю без него.

## Новый внешний сервис на сайте (счётчик, виджет, чат)
Если у сервиса свой скрипт — вписать его домен в CSP `script-src` в `public/.htaccess` (три строки с `Content-Security-Policy`), иначе браузер его не запустит. Перед этим проверить, что сервис не собирает данные посетителей без согласия.

## PDF для клиента
`python3.13 scripts/md-to-pdf.py in.md out.pdf`. Шрифт Manrope в `scripts/.fonts/`. Эмодзи в PDF не отображаются (квадраты) — в документах их не ставить. Строки, которые должны идти отдельно, разделять пустой строкой.

## После перезапуска облачной сессии
- `npm ci` (иначе `npx tsc` может подтянуть чужую версию TypeScript).
- Плагины скиллов ставятся скриптом окружения Default сами. Проверить: `claude plugin list`. Если нет — команды из `context/handoff.md`.

## Частые поломки
| Симптом | Причина и что делать |
|---|---|
| Сайт «Не защищено» | Истёк сертификат — выпустить в ISPmanager (см. выше). Если снаружи всё ok — кэш браузера. |
| Бот молчит | «Site check» → вебхук: `last_error_message`. 401 — дождаться автоперепривязки или нажать переподписку в админке. |
| Пост в MAX кривой (дубль цены, пустые ◾) | `maxPostHtml` в воркере: строки поста склеиваются до разбора; проверить на тексте поста. |
| Внешний скрипт не работает | Не вписан в CSP `script-src`. |
| В /crm 403 | На хостинге появилась папка `/crm/` — удалить (API живёт в `/crm-api/`). |
| Фото каталога не грузятся | `/api/mediadiag` — место на диске и кэш медиа. |
